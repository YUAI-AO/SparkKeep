# 续火花 · Android 版

和电脑版用的是同一份界面代码（`app.html` 直接打进 APK 里），六页导航、液态玻璃、入场转场、时间轮盘、勾选逻辑都一样；
区别只是把「开机自启的 Windows 程序」换成了「安卓前台服务 + 开机广播」。

- 包名：`com.spark.keep`　版本：1.0.8（versionCode 26）
- 最低系统：Android 7.0（API 24），目标 API 34
- 体积：104.8 KB，无第三方依赖，不联网除抖音自身域名

## 版本记录

从 **v1.0.0 起**每次发版在下面追加（记录只留在本文档，App 里不再放版本面板）；
1.0.0 之前的 1.5–1.16 属于改版前的旧账，不往回收，只留在后面的历史小节里。

### v1.0.8 · 2026-11-11（versionCode 26）

全量回归（Windows API 24 项、Android Bridge 33 项、Android UI 26 项、Windows 页面 23 项）挖出来并修掉的缺陷：

- **任务通知残条撤不掉**：「正在惊醒中 · 人名」那条是 `ongoing` 的，用户划不掉。旧逻辑只在内存标记 `jobNotiOn` 为真时才撤，而服务被 `onTaskRemoved` 重建或进程被系统回收后这个标记是 false，通知栏里那条就永远挂在那儿。现在任务不活跃时**无条件**撤一次。
- **调试端口 9411 全机共用 → 可能劫持用户真实浏览器**：桌面端多个实例（连同测试实例）都用同一个 9411，谁先占谁说了算，测试实例会复用用户正在用的 Edge 并真的发出消息。改为按 profile 路径 CRC32 派生端口（`9411 + crc32 % 180`），各实例互不干扰。
- **好友页「保存勾选」被空名单保护吞掉**：用户主动清空名单时服务端按「防手滑」规则保留了原名单，表现是点了保存没反应。保存请求现在带上 `allow_empty`，轮询的自动提交仍受保护。
- **设置页缺少联系邮箱**：电脑端补上「联系」卡（`aolikeyou@outlook.com`），手机端原本就有。
- 移除两处 `will-change:opacity`（省内存，浏览器自己决定提升即可）。
- 发送链路单条失败自动重开会话重试一次，文案标注「（重试成功）」。

### v1.0.7 · 2026-11-11（versionCode 25）

- **低占用**：任务通知的巡检从固定 1.2 秒一次改成「跑任务时 1.2 秒、空闲 8 秒」——空闲时一天的唤醒从 7.2 万次降到 1 万次出头。为了不让转圈通知迟到，任务状态一变就由 `Spark.jobHook` 立刻踢一脚，不需要等巡检周期。
- 服务销毁时解绑 `jobHook`，避免回调指向已停止的服务。

### v1.0.6 · 2026-11-11（versionCode 24）

- 关于卡加入题记「天地本宽而鄙者自隘」，样式与电脑端一致（等宽字体、字距 0.2em、40% 透明）。

### v1.0.5 · 2026-11-10（versionCode 23）

- **退出应用后通知消失**，三个原因一起修：
  - 通知被系统「一键清理」或划掉任务时连带抹掉，而旧逻辑只在内容变化时才重投，抹掉就再也不回来 —— 现在每分钟检查一次自己那条通知还在不在，不在就补投一次；
  - 从最近任务划掉应用时，旧逻辑只排了个 15 分钟的闹钟兜底，某些 ROM 直接杀进程，通知栏空一大截 —— 现在 `onTaskRemoved` 里立刻重新拉起前台服务，闹钟只作二次保险；
  - Android 13+ 通知权限若没授予，前台服务通知不会出现在通知栏（服务其实在跑）。设置页「权限与放行」里的「通知」可以一键申请/跳转，务必给上。
- 服务声明显式 `stopWithTask=false` 的语义保持：划掉界面只释放 WebView 内存，后台继续跑。

### v1.0.4 · 2026-11-10（versionCode 22）

- **修掉「手机端整页下移」**：状态栏透明后，`--safe-top` 原来直接把 insets 的**物理像素**写进页面，而页面里 1px 是 CSS px（dp）。2.75 倍屏上等于把页面往下推了近 70dp。现在先按 `density` 除一遍再取整，只留原有的 24dp 呼吸。

### v1.0.3 · 2026-11-10（versionCode 21）

### v1.0.2 · 2026-11-10（versionCode 20）

- **切页不再「先透明再糊上」**：根因是 `.view` 进场那个 0.16 秒的 opacity 动画——动画那几帧内核拿不到背景快照，玻璃卡的 `backdrop-filter` 会被算成无模糊。现在整页硬切，不做淡入；实测切页首帧（39 ms）`backdrop-filter` 就已经是最终值。
- **卡片模糊最低就是不模糊**：滑片拉到 0 不再保底 12px，只留 `saturate(138%) brightness(1.03)` 的透亮感，`--glass-blur-sm` 按同比。
- 设置页里的「屎山迭代」版本面板整块删掉，以后也不再做；版本号只留在关于卡和本文档。
- 权限卡、自动化卡、联系卡里剩下的解说行一并删掉，只剩标题 + 状态 + 控件。
- 右下角任务通知：任务跑起来时显示「正在惊醒中 · 当前人名」+ 转圈，任务结束整条撤走（页面内 toast 与系统通知两条都改）。

### v1.0.0 之前（改版前的旧账，只留档，不再维护）

## 怎么装

1. 把 `SparkKeep.apk` 传到手机（微信/QQ/数据线都行）。
2. 点开安装，系统提示「未知来源」时选**允许**（调试签名，不是应用商店包）。
3. 打开 App，第一次会先弹一张「先说几句」（仅用于学习与研究、账号与手机问题与作者无关），点「知道了，继续」才往下走；
   紧接着是通知权限，选**允许**——这是后台常驻通知，关掉就看不到「保活中」状态。

## 第一次要做的三件事

1. **登录抖音**：主页「登录抖音」或账号页「登录抖音」→ 应用会用**电脑版页面**打开抖音首页（手机版网页只有"下载抖音"引导页、没有二维码），
   进入后自动帮你点右上角「登录」，二维码就出来了。扫完按返回键回到程序，程序会自动核一次登录态。
   Cookie 存在应用私有目录，之后自动发送直接复用，不需要再扫。
   （若二维码没自动弹出，手动点页面右上角「登录」即可；页面是电脑版，字小可以两指放大。）
2. **读一次会话列表**：好友页点「重新读取」→ 会拉出所有会话和火花天数，勾选要续的人 → 保存勾选。
   读取的那几十秒里，屏幕会切到真实的抖音私信页（顶部一条提示，读完自动收起）——
   抖音的会话列表是懒加载的，页面必须真的被渲染才知道谁有火花；按返回键可以先收起来，读取照旧在后台跑。
   要是读完还是 0 个，去「记录」页看那行红字，里面写着页面停在哪（URL、标题、抓到几个会话节点）。
   （开了「自动纳入有火花的人」的话，每次到点会自动把有火花、非群聊的人并进名单。）
3. **设时间**：计划页调好每天的时刻与随机抖动，写几条文案，保存计划。

## 后台保活（设置页 →「后台与保活」）

| 开关 | 作用 |
| --- | --- |
| 保持后台运行 | 常驻一个低优先级前台服务。关掉界面（返回键 / 最近任务划掉）不会停它，照常按点续 |
| 开机自动启动 | 收 `BOOT_COMPLETED`，开机后自己把服务拉起来，不用你手动开 App |

同一块里还有三枚状态徽标（后台服务 / 电池白名单 / 网页内核），下面一行「离开后释放」就是界面内存的延迟归还时间。

## 关于「退出」

- 按返回键 / 上滑回桌面 / 切到别的 App → 界面的整块 WebView **等 30 秒**再销毁（`destroy()`），**后台服务不动**，到点照续。
  这个 30 秒可以在设置页 →「后台与保活」→「离开后释放」里调（0 = 立刻释放，最大 120 秒）。
  留这几十秒是为了切回来时秒开；真要走内存就让它在后台待着，30 秒后自动归还。
- 设置页最下面的「退出程序」才是真的全停：前台服务、闹钟、任务线程一起结束。

## 它到底怎么干活

- 每天到设定时刻（含 ±抖动）醒一次 → 用隐藏的 WebView 打开抖音私信页 → 采集会话列表与火花状态
  → 找出「今天两人都还没互动」的人 → 逐条发一条随机文案（间隔 2~5 秒随机）→ 关闭页面回收内存。
- 不用无障碍、不 root、不注入抖音 App；就是一个普通的网页会话在跑，频率一天一次。

## 权限与放行（设置页 →「权限与放行」）

六项一次性列清，右边是状态徽标（已开启 / 未开启 / 手动），能自动跳的都有「去设置」：

| 项 | 怎么处理 |
| --- | --- |
| 通知 | 常驻状态 + 失败提醒都靠它。没开就点「去设置」授权 |
| 电池优化白名单 | 点「去设置」→ 系统弹窗选「允许」，或直接点下面的「一键放行电池优化」 |
| 精确闹钟 | `SCHEDULE_EXACT_ALARM`，Android 12+ 需要手动给，不给只会延迟几分钟 |
| 自启动 / 后台运行 | 各家 ROM 各不相同，程序会依次尝试小米 / 华为 / ColorOS / OPPO / vivo / 三星 / 魅族 / 传音的跳转入口，全不中才退回应用详情页 |
| 多任务锁定 | 在最近任务里长按本卡片加锁，系统清后台时能留下 |
| 相册 / 文件 | 选壁纸走系统选择器，不需要额外权限 |

按钮「重新检测」只读系统状态、不改任何设置，点一下就能看到当前六项的真实状态。

## 已知限制（如实说明）

- **最关键的一条：能不能读到会话，取决于手机自带的网页内核版本。** 抖音 2026 的私信页需要 Chrome 95 以上；
  内核太旧时网页会一直停在「加载中」，会话列表永远是 0，登录页也拿不到二维码 —— 这不是程序逻辑的问题，
  是网页组件本身跑不动那套前端。设置页「后台与自启」里那行「网页内核」就是自检：
  显示 `Chrome 83 · 过旧` 就是内核不够；显示 `Chrome 110` 之类的数字就没问题。
- 我这边只有一台 Android 11 模拟器（系统自带 WebView 是 Chrome 83），所以整条链路是在这个偏旧的环境里验出来的：
  编译、签名、界面渲染、Cookie 判定、并发加锁、读取为空时的现场记录都验证过；
  **「内核够新的机器上一定能读到列表」这一点，我无法在这里直接证明**（这台机器上网页自己就加载不出来）。
- 抖音网页版形态会随版本变化；真机若读完还是 0，把记录页那行红字发我，我按现场继续调。
- 应用图标是五档普通 mipmap（没有做 Android 8+ 的自适应图标），个别启动器会给方形图加白边。

## 1.2 修了什么（本轮）

- **读不到列表**：原来那块 WebView 是不挂到窗口的，Chrome 会停掉渲染帧，抖音的懒加载会话列表永远出不来。
  现在读取时把它真挂到界面上（可见 → 正常渲染），读完自动摘掉；同时改用 Activity 作 WebView 的 context（用
  application context 建 WebView 拿不到宿主主题，容易白屏）。读不到时把页面现场（URL / 标题 / 节点数 / 正文前 160 字）写进记录页。
- **登录态横跳**：判定改成看 WebView 的 Cookie 里有没有 `sessionid`（毫秒级、稳定），不再为了检测去开一次 40 秒的页面。
  检测接口改成同步返回，向导第 2 步不会再出现「上面写已登录、下面 toast 说没检测到」。
- **并发抢同一块 WebView**：读取、检测、定时发送三条流程加了一把锁，同一时刻只有一个在用它，状态不再互相打断。
- **状态栏压住页面顶部**：刘海/状态栏高度改加到最外层容器上（之前加在 WebView 上被它自己消费掉了）。
- 「读取完成」toast 改成「读取中，几秒后自动刷新」——读取是后台线程，原来那句在结果回来之前就弹了。

## 1.3 修了什么（本轮）

这一轮没有再瞎改逻辑，而是先在模拟器里把根因挖出来了，所以改动都是冲着根因去的。

- **设置页新增「网页内核」一行**：直接显示系统 WebView 的 Chrome 主版本号；低于 95 会标红「过旧」并给出更新办法。
  这是本轮最重要的一行 —— 它把「读不到列表 / 没有二维码」的原因变成一眼能看见的事实。
- **登录态不再来回跳**：以前「没有 Cookie」时会沿用上一次存下来的「已登录」，界面一会儿已登录一会儿没登录。
  现在没有 Cookie 就明确判未登录；反过来，只要**真的读到了会话**，就以「能读到数据」为准回写已登录（比读 Cookie 更可靠）。
- **去掉了每次检测都开一次聊天页的行为**：旧代码在无 Cookie 时会开页面等 20 秒去「猜」登录态，
  既吃内存又抢同一块 WebView，是界面抖动和卡顿的来源，现在这条路彻底删掉。
- **首屏卡在「加载中」会自动重载一次**：抖音首屏第一次加载失败的几率不低，以前直接报 0；现在会自己重载再等，
  实在还不行才把现场写进记录页。
- **页面自检**：设置页「页面自检」按钮会把真实私信页挂到界面上停 15 秒，让人肉眼看清它到底停在哪，
  同时把 URL / 标题 / 会话节点数 / 正文前 160 字写进记录页的 `AUTH` 行。

## 1.4 修了什么（本轮 · 功能完整性检查）

这一轮把 13 个接口、6 个页面、前台服务、通知、计划存取、壁纸、勾选逐个跑了一遍，查出 4 个真 bug。
前三个已改好并在模拟器上复验通过，第四个判定为设计如此。

1. **每分钟无限重试（最严重）** —— 以前失败什么都不记，`last_run_date` 永远不落盘，服务的每分钟 tick 又重跑一次，
   于是「到点 → 打不开私信页」一天刷几十上百次：耗电、耗流量、界面被它卡住、状态显示一直在跑。
   现在每次失败都记账，**当天连续两次不成功就锁住自动重试**（记录页会写「今天连续两次没成功，不再自动重试」），
   两次之间至少隔 10 分钟；想再试就点「立即执行」手动跑一次。
2. **「重新读取」按钮其实没去读** —— 这个按钮原来发的是 GET，安卓桥是同步的，GET 只把内存里的旧缓存原样返回；
   点一百次也不会有新列表，**这才是「读完还是 TOTAL 0」的直接原因**。现在改成 POST，会真的开页面去抓，
   并且立刻把现场（URL / 标题 / 节点数 / 正文）写进记录页。
3. **关掉界面没还内存** —— 按返回键时系统只是把任务挪到后台（Activity 不销毁），整块 WebView 一直留着。
   现在一离开前台就销毁 WebView，回到前台重新挂一份；实测后台时 `WebViews` 归零、前台服务照常活着。
4. **清空勾选后配置里还留着名字** —— 接口只把 `enabled` 置 false、不删条目。判定为设计如此：
   「清空」= 全部取消勾选，名单留着（下次读取还能一眼看到谁被排除），不影响发送。

顺带确认没问题的：13 个接口全部通（`ping / state / selftest / logs / friends / settings / wallpaper /
login / account/check / send-now / stop / keep / quit`）；六个页面都正常渲染；前台服务 `isForeground=true`、
常驻通知「续火花后台待机」在；计划的时刻与抖动写入后读回一致；自定义壁纸能正常显示（`<img>` 加载 200、尺寸正确）。

**没实测的**：`send-now`（一点就真的会给好友发消息，所以只验证了会被「正在发送中」挡住、不会重复跑，没有真发）、
开机广播（需要重启整台机器，模拟器上没做）、真机上的内核版本（要你装了才知道，设置页那行会显示）。

## 1.5 修了什么（本轮 · 手机端重做 + 五个真 bug）

这一轮按你列的要求把手机端整体重做了，同时揪出五个真 bug，其中两个是「你觉得某个功能坏了」的真正原因。

### 先说三个真 bug

1. **「立即发消息」显示完成但其实没发（最要命）** —— 任务收尾那行不管成败都把 `done` 写成总数，
   于是一条没发出去也显示 5/5 完成。现在按真实结果算：`完成 · 成功 N / 失败 M`，
   记录页再补一行「本次结束 · 成功 N 条 · 失败 M 条」。
2. **壁纸点了没反应** —— 两处叠加：① WebView 根本没挂 `WebChromeClient`，`<input type="file">` 点了等于没点；
   ② 页面里 `#wall / #veil / #grain` 用的是 `inset:0`（Chrome 87 才有的简写），老内核上这几个全屏层**尺寸塌成 0**，
   所以壁纸也永远显示不出来、压暗也永远不起作用。现在补了 `onShowFileChooser`（走系统选择器，`ACTION_GET_CONTENT`），
   并把 7 处 `inset:0` 全改成四向定位。改完壁纸立刻正常，液态玻璃也终于真的是「透」的。
3. **失败没有任何提醒** —— 现在每次跑失败都会发一条高优先级通知（独立频道 `spark_alert`、震动、角标、可展开长文本），
   全失败和部分失败用不同标题，第一条失败原因跟着一起给；点通知直接回到 App。

### 再说你点名要的

- **退出后延迟释放**：设置页「后台与保活」多了「离开后释放」滑片，0–120 秒、默认 **30 秒**；
  切回前台会撤销这次释放，内存不会白扔。0 就是以前那种立刻释放。
- **权限自检 + 一键放行**：新增 `/api/perm` 接口与「权限与放行」整块（六项状态 + 去设置 + 重新检测 + 一键放行电池优化），
  自启动会依次尝试 9 个国产 ROM 的跳转入口，全不中才退回应用详情页。
- **「重新读取」真的会去读**（1.4 里已修，本轮复验）：点完记录页确实出现现场记录，触发链路成立。

### 界面：整块重做

- **删掉所有卡片右上角的 `SEQ 01`**（11 处，另加一条兜底 CSS）。
- **页面签挪到底部**：手机上导航整条横向铺满，六项等分、图标在上中文在下，点按切换；
  另外支持**左右滑动切页**（横滑 56px、横纵比 1.2、700ms 内生效）。
- **切页不再跳动**：抖动来自「每个子元素各延迟 24ms 下移 7px 再归位」+「每次切页 `scrollTop` 归零」。
  现在改成整块 `.16s` 淡入没有任何位移，并且切走时记住该页的滚动位置、回来还原（`requestAnimationFrame` 再补一次）。
- **统一配色与透明度**：一套灰阶（`#EDF0F2 / #97A0A6 / #6C7479 / #454B4F`）、单一强调色 `#D9F24C`、

- **设置页分类重排**：显示 / 自动化 / 后台与保活 / 权限与放行 / 诊断 五块，每块一条细线收住、没有序号。
  「显示」里两条滑片分得很清——上面那条只管壁纸，下面那条只管卡片，中间直接写了这句提示。
- **昼夜切换**：显示块里的「深色 / 浅色」分段，整套变量跟着换（含底部导航与卡片）。
- **好友列表只留四样**：勾选框、头像、名字、火花天数。右侧四段竖条、状态小点、名字下面的时间与消息全删了，

## 1.13 修了什么（键盘遮挡 · 切页提速 · 一堆看不清的地方）

这一版是把「用起来会硌人的地方」逐个找出来按掉，共七类，每类都在模拟器上装包复测过。

### 1. 软键盘挡住输入框（影响最大的一条）

Android 11 起 `MainActivity` 用 `setDecorFitsSystemWindows(false)` 全屏铺开，`applyInsets()` 却只读
`WindowInsets.Type.systemBars()`——那里面**不含输入法**。结果是键盘弹出来、窗口纹丝不动，
计划页的「文案池」输入框被键盘整块盖住，只能盲打。

改法：`applyInsets()` 同时读 `WindowInsets.Type.ime()`，底部内边距取 `max(系统栏, 输入法)`：

```java
int ime = 0;
if (Build.VERSION.SDK_INT >= 30) {
    ime = insets.getInsets(WindowInsets.Type.ime()).bottom;
}
v.setPadding(0, top, 0, Math.max(bottom, ime));
```

## 1.12 改了什么（模糊拆开 · 关于/免责/邮箱 · 切页再优化）

### 1. 卡片模糊和壁纸模糊，彻底分成两根滑片

1.11 把两根合成一根是错的：那根叫「玻璃模糊」，实际同时驱动壁纸和卡片，等于用户想只调卡片也做不到。现在 `app.html` 里是两个互不相干的变量：

| 滑片 | 改的变量 | 作用对象 |
| --- | --- | --- |
| 壁纸压暗 | `--veil` | `#veil` 那层压暗 |
| 壁纸模糊 | `--blur` | `#wall { filter }`，只有背后那张图 |
| 卡片不透明 | `--card-a` | 所有卡片 / 按钮的底色透明度 |
| 卡片模糊 | `--glass-blur`（小面板用 `--glass-blur-sm`） | 卡片的 `backdrop-filter` |

实测：壁纸模糊拉到 7 → `--blur: 7px`，而 `--glass-blur` 仍是 `none`；再把卡片模糊拉到 9 → `--glass-blur: blur(9px) saturate(118%) brightness(.97)`，此时 `--blur` 依然停在 `7px`。**两根滑片不再互相串。**

配置里对应 `appearance.blur`（壁纸）与 `appearance.blur_card`（卡片），都是 0 起步——默认全关，省内存。

### 2. 卡片不透明度在「扁平」风格下也生效

`body.plain` 以前把 `--glass` 写死成 `rgba(17,19,21,.94)`，比 `:root` 更近，直接压掉滑片写进去的值，所以切到「扁平」之后那根滑片就失效了。
现在扁平风格的底色也由 `--card-a` 驱动，并补了浅色主题分支（不然浅色 + 扁平会变成深色卡片）。
实测：扁平状态下卡片 `background-image` = `linear-gradient(rgba(17,19,21,0.42), rgba(13,14,16,0.42))`，和滑片上的 42% 一致。

### 5. 切页还是卡 —— 这次是量过之后改的

在模拟器里拆开计时（设置页，最重的一页）：

| 阶段 | 耗时 |
| --- | --- |
| 生成 HTML 字符串 | 28.8 ms |
| `innerHTML` 解析 + 布局 | 26.7 ms |
| 绑定事件 | 7.8 ms |
| **合计** | **约 63 ms** |

可见「卡一下」主要不是动画，是每次切页都**整页重建 DOM**。所以：

- 切页动画从 `translate3d(±12px) + opacity` 换成**纯 opacity、0.12s**：带位移的版本会让整块 393×751 的视图每帧新建合成层（背后还压着壁纸/压暗/网格三层 fixed），等于每帧整屏重绘。位移只有 12px 肉眼几乎看不出，代价却是整屏。
- `goPage()` 里先把 `view.scrollTop` 归零再渲染，避免「重建 DOM 的同时还在滚动」叠一次重排。
- `navsw` 期间除卡片 `backdrop-filter` 外，壁纸的 `filter` 也一起摘掉（壁纸模糊开着时每帧要对整屏重算高斯）。
- `goPage()` 现在会写 `window.__navdt`（本次切页耗时，毫秒），以后排查直接读这个数。

模拟器是 swiftshader 软件渲染，真机的这 63 ms 通常会短不少；但把动画的整屏重绘去掉是实打实的省。

## 1.11 修了什么（发不出消息 · 模糊滑片 · 切页卡顿）

这一轮是三个真 bug，不是调样式。

### 1. 消息发不出去 —— 用假键盘事件去按真编辑器

桌面版发消息走 Edge CDP 的 `Input.dispatchKeyEvent`，那是**真实按键**（`isTrusted=true`），抖音的编辑器照常处理。
Android 版没有这条路，之前用 `dispatchEvent(new KeyboardEvent('keydown', ...))` 自己造了一个**假按键**——
`isTrusted=false`，编辑器直接忽略。于是流程每次都退化成「点发送按钮」，而按钮候选的写法是
`querySelectorAll('button, [role="button"], div')` 全页面扫一遍、按宽度从大到小取第一个，
点到的常常是输入框容器之类的大 div，什么也没发生。最后程序拿「输入框是不是清空了」当成发送成功，
所以界面上写着完成，消息一条没出去。

改法三处：

- **回车走 WebView 的真按键管线**：`wv.requestFocus()` + `wv.dispatchKeyEvent(ACTION_DOWN / UP, KEYCODE_ENTER)`，
  事件由系统输入栈产生，是可信事件，编辑器的原生处理路径才会跑。
- **发送按钮的定位收窄**：先 `[data-e2e*="send"]`，再文本等于「发送」的元素，最后才是 `button / [role="button"]`；
  全部限定在输入框同一水平线、且位于它右侧，**不再把整页 div 当候选**。点的时候补全
  `pointerdown / mousedown / pointerup / mouseup / click` 一整串，把 React 那条路径喂饱。
- **成功判据换成「消息真的出现了」**：发送前先数一遍页面上有几条这条文本（排除输入框自身），
  发送后只有**数量变多**才算成功。三路依次尝试（真回车 → 发送键 → 再回车），全失败才判失败，
  并把 `同文本 0→0→0→0、发送键=no-btn、输入框剩=空` 这样的现场写进记录页的 ERROR 行，同时弹失败通知。

**这一条我没法在模拟器上端到端验证**——模拟器里抖音是未登录状态，会话列表读不出来，发送链路走不到。
能保证的是：假成功这条路已经被堵死（判据从「输入框清空」换成「消息出现在会话里」），
所以真发不出去时你会**收到失败通知**、记录页也会写明卡在哪一步，不会再安静地显示完成。

### 2. 「玻璃模糊」滑片拉到底也没反应

`applyLook` 里那根滑片只写了一个变量 `--blur`，而它只作用在**壁纸**上（`#wall { filter: blur(var(--blur)) }`）；
卡片的背景模糊走的是另一个变量 `--glass-blur`，这个值在样式表里**写死成 `blur(22px)`**，没有任何代码碰过它。
所以滑片怎么拉，卡片一直是 22px 的毛玻璃——名字叫「玻璃模糊」，实际管的是壁纸。

现在壁纸和玻璃共用一个值：`0` 时两边都 `none`，`>0` 时卡片用 `blur(Npx)`、小面板用 `blur(N×0.6px)`，
拖动即时可见（不用等松手保存）。实测滑到 12 → `--glass-blur = blur(12px) saturate(118%) brightness(.97)`，
卡片 computed `backdrop-filter` 同步变成 `blur(12px) saturate(1.18) brightness(0.97)`。

顺带把默认值改成 **0（全关）**：原来哪怕滑片显示 0，卡片也在做 22px 高斯，纯白吃内存，
和「一切以低占用为前提」矛盾。想要原来那层糊感，把它拉到 6~10 就行。

### 3. 切页那一下卡顿

`backdrop-filter` 不是免费的：每个卡片都要在**每一帧**重新对背后那片区域做一次高斯。
切页时十几块卡片同时重建图层，模糊开得越大越明显——这就是「切页卡一下」。

现在切页动画那 0.26 秒里，先给 `body` 挂 `navsw`、把卡片/按钮/顶栏/侧栏的背景模糊临时摘掉，
动画只走 `opacity + translate`（合成层就能完成），结束再装回去。默认模糊 0 时这段完全无感；
把模糊拉到 10 以上，切页会在这 0.26 秒里看到卡片"变清"，换来的是不卡。

### 实测过的

- 模糊滑片：0 → `--glass-blur:none`、卡片 `backdrop-filter:none`；12 → `blur(12px) …`、卡片同步生效。
- 切页：`navsw` 挂上时卡片 `backdrop-filter` 为 `none`，260ms 后自动消失并恢复。
- 正式包（`debuggable=false`、versionCode 12）卸载重装：能起、Activity 在前台、前台服务 `isForeground=true`、常驻通知 1001 在。

### 仍然没实测的

发消息的端到端结果（模拟器无登录态）。如果真机上仍然发不出去，记录页那行 ERROR 会写明卡在
「找不到输入框 / 文本没有进入输入框 / 没能确认发出（同文本 0→0→0→0，发送键=…）」，把那行发我就能直接定位。

## 1.8 优化了什么（本轮 · 优化手感）

这一轮不改任何布局尺寸，只改「手指碰上去的感受」。

1. **点击延迟（最直观的一条）** —— 安卓 WebView 默认会先等约 300 毫秒，判断你是想点一下还是想双击放大，
   所以点任何东西都会「愣一下」才响应。给全站加 `touch-action:manipulation` 把这个等待去掉，按下即触发。
2. **主按钮按下去不缩（这是真 bug）** —— 探针量出来的：`.btn:active{scale(.97)}` 本来是有的，
   但主按钮为了做光晕单独重写过一遍 `transition`，把 `transform` 丢了。
   结果就是**次要按钮按下去会缩一下，「立即续一次」按下去毫无反应**——最该有反馈的那个最木。
   补回后按下缩到 97%，0.12 秒回弹。
3. **长按会弹系统菜单 / 会选中文字** —— 全站 `-webkit-touch-callout:none`，非输入元素 `user-select:none`，
   输入框（时间、数字）仍然可以正常选字复制。
4. **底部导航原来只有 31px 高** —— 手指按不准。抬到 39px（+26%），整个导航条 60 → 68px。
5. **开关的球、滑片的滑块** —— 按下时球收一下（0.86），拖动滑块时放大（1.16），给「抓住了」的确认感。
6. **输入框聚焦** —— 给一圈极淡的强调色描边，知道自己在改哪一格。
7. **切页的方向感** —— 左滑看下一页时，新页从右侧 12px 滑进来（150ms，快出慢收的曲线）；
   点页签时位移为 0，只有淡入，所以定时刷新的周期重绘不会多出任何位移。

### 实测过的

- `touch-action` 计算值：`manipulation / manipulation`。
- `.btn.pri` 的 transition 现在含 `transform 0.12s`（改前没有）。
- 底部导航：`h 31 → 39`，导航条 `60 → 68`。
- **真手势滑动**（用 `input swipe` 模拟手指，双向都试了）：
  `settings` 页左滑被正确拒绝（已经是最后一页）；`log` 页左滑 → `settings`；`settings` 页右滑 → `log`。
- 正式包（`debuggable=false`、versionCode 9）全新安装：能起、Activity 在前台。

### 仍然没实测的

「按下缩一下」这个动作本身是用计算样式验证的（量到 transition 里有 transform、`:active` 规则命中），
不是录屏逐帧看回弹曲线；真机上不同机型的手感轻重还需你自己上手感受。

## 1.7 修了什么（本轮 · 功能完整性复查）

按你说的「检查功能完整性」，这一轮把 14 个接口、6 个页面、通知链路、权限链路、释放延迟都实际跑了一遍。
**查出 2 个真 bug，都不是界面问题，而是「你以为能用、其实会被系统悄悄掐掉」的那种。**

1. **失败提醒会被系统降噪（最要命）** —— 常驻通知原来每 60 秒无条件重投一次同一个 id，一天 1440 次。
   安卓会给这种反复重投的通知打「降噪」标记，`dumpsys notification` 里能看到：
   `post_frequency{count=196, demoted=192}` —— 也就是说 **196 次里 192 次被系统降级了**，
   连同一条包里的失败提醒一起被降级，你自然收不到。
   现在只有通知内容真的变了才重投（标题/正文拼成 key 比对），并加了 `setOnlyAlertOnce(true)`。
   实测：装上修复后的包，静置 4 分 10 秒，`count` 从 200 到 200，**一次都没有增长**（改之前是每分钟 +1）。
2. **持续故障会把提醒刷成骚扰** —— 未登录这类故障会让每分钟的 tick 都失败，以前每次失败都发一条通知。
   现在同一条提醒 **10 分钟内只响一次**，故障持续也不会刷屏，但第一次一定响。

### 这一轮实际验证过的（全部真机实跑，不是推断）

- **14 个接口**：`ping 2ms / state 10ms / logs 3ms / friends 10ms / settings 4ms / account/check 53ms /
  wallpaper 2ms / keep 3ms / perm 6 项` 全部返回正常；
  `stop` 在无任务时正确返回 `当前没有任务`（这是应有的行为，不是失败）。
- **6 个页面**全渲染出内容（概览 60 节点 / 账号 30 / 好友 14 / 计划 55 / 记录 15 / 设置 117）。
- **界面要求逐条核对**：`SEQ` 残留 **0** 处；底部导航 `top=691 bottom=751 vh=751` 贴底、6 项齐；
  `goPage` 函数在（左右滑动依赖它）；四条滑片分组正确——`壁纸压暗 58% / 卡片不透明 42%` 一组，
  `玻璃模糊 0 / 离开后释放 30s` 各自归位；`--fg #EDF0F2`、`--card-a .42`、`--veil .58` 与设定一致。
- **权限六项真实状态**：`notification=ok / battery=need / alarm=ok / boot=manual / recent=manual / storage=ok`。
- **失败提醒实测**：故意在未登录状态触发一次发送，任务失败后通知栏出现
  `id=1002 · channel=spark_alert · importance=4 · 标题「续火花这次没跑成」`，常驻 `id=1001` 同时在线。
- **释放延迟**：`/api/keep` 返回 `release_delay: 30`，`boot_start/keep_alive` 均 true，`wv 83 / wv_old true`。

### 仍然没实测的（如实说明）

开机广播（要重启整机）、好友列表真实数据（模拟器内核 83 读不到抖音会话）、
`selftest / login / quit` 三个接口本轮没有触发（它们需要真登录态或会直接退出进程）。
